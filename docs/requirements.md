# 要件定義

確認日：2026-09-09。前回案を撤回した後の対話で合意した初期版の要件をまとめる。ここにある要件の採用と、実機での実現確認は別である。

## 目的と範囲

参加者がボタンを一つ押すと、管理者が公開した構成へ専用インスタンスを更新し、Minecraftを起動して参加先へ接続する。公開セットを変更したときも、参加者が必要な版を自分で探して組み直す作業を減らす。

| ID | 項目 | 初期版の要件 |
| --- | --- | --- |
| R01 | 利用者 | 管理者本人と友人、合計最大8人程度。人数を強制制限する機能は要求しない |
| R02 | 環境 | Windows 11、Prism Launcher、Minecraft 1.21.1、NeoForge |
| R03 | 参加先 | 管理者本人が運営するAGAMESのMinecraftサーバー |
| R04 | 対象環境 | 新しく作るサーバー専用インスタンス。他のインスタンスを更新対象にしない |
| R05 | 基準環境 | 管理者の「All of Create - Aeronautics」で初回作成・更新・復元・参加を検証する |
| R06 | 拡張性 | 別のMinecraft版・Forge・Fabricへ将来拡張できるようにする。初期版での動作保証はR02の範囲 |

ローカルの基準環境はMinecraft 1.21.1、NeoForge 21.1.228、FTB Quests 2101.1.24だった。21.1.228は今回の検証開始点であり、プログラムに恒久的に埋め込む値ではない。配布セットには必要な正確な版を記録する。

## 管理者と参加者の分担

**管理者**はAGAMES側のMOD・クエストなどを手動で更新する。自分のPrism環境で参加・動作を確認し、管理者ツールで配布するMOD、指定設定、リソースパックなどを選ぶ。選択後の配布内容を固定し、その内容だけから新しい検証用インスタンスを作って、実際の参加・必要なパック・クエストを確認する。確認済みの内容について「公開」を押すと、配布用サーバーへアップロードする。元のPrism環境での参加確認だけでは公開可能にせず、配布内容を変更したら再検証する。編集だけでは公開済みセットを変えない。

**参加者**は公開済みセットを取得し、専用インスタンスを更新して参加する。ツールによるAGAMESのMinecraftサーバーの自動更新は初期版の範囲に含めない。

## 同期ルール

| ID | 対象 | 同期時の動作 | 管理者が指定を外した場合 |
| --- | --- | --- | --- |
| R07 | 必須MOD | 全員へ共通のセット。指定版へ自動で揃え、必要なら古い版へ戻す | 以前ツールが管理していたMODを稼働環境から外す |
| R08 | 個人MOD | 参加者がクライアント用MODを追加できる。同じMODが必須指定と重なる場合は管理者指定の版を優先する | 個人で追加した別MODは保持する |
| R09 | 指定設定 | 管理者が選んだファイルを丸ごと上書きする | ファイルは残し、以後の上書きを止める |
| R10 | 指定外設定 | 現在の内容を保持する | 保持する |
| R11 | 配布リソースパック | 配布して自動で有効化する。配布パック同士の順番は管理者指定に揃える | 以前管理していたパックを無効化し、稼働環境から外す |
| R12 | 個人リソースパック | 保持して利用できる。重なるリソースは配布パックを優先する | 保持する |
| R13 | クエスト | 管理者がサーバーの定義を整え、参加時にFTB Questsが内容を同期する | 定義変更は管理者が行う。ツールで進捗を配布・上書きしない |

サーバーのみ・クライアントのみ・両方で使うMODという分類と、必須・個人追加という管理区分は分ける。クライアント専用の必須MODも扱う。Sodiumはこの説明の例であり、必須指定が決まったわけではない。管理者が任意のおすすめMOD一覧を配る機能は設けない。

クエストで揃えるのは課題・説明・報酬などの内容。プレイヤー・チームの達成状況はツールの同期・復元対象にしない。定義変更がゲーム内の達成判定に一切影響しないという保証ではない。

リソースパックの自動有効化には関連する設定の変更が必要になる。ファイル丸ごとのコンフィグ同期とは分け、必要な項目だけを変更して他の設定を保持する設計を[設計案](design.md)に示す。

## 初回と通常の操作

- **R14 初回案内**：Prism未導入の場合は、ツールが導入・初期設定・Microsoftログインの手順を案内し、本人が操作する。
- **R15 専用環境の作成**：ツールの案内で新規インスタンスを取り込む。Prismが表示する取り込み確認は本人が確定してよい。
- **R16 通常の参加**：構成の更新、Minecraft起動、サーバー接続を一つの参加操作で進める。起動直前に公開中の版を再確認し、待機中などに版が変わっていたら新しい版への更新を進める。最新版を確認できない間は起動せず、連続変更への自動追従には上限を設ける。
- **R17 手動取得の例外**：自動取得できないMODだけ、必要な版のダウンロード開始用リンクを直接示す。取得した全件の内容を確認できたら自動で再開し、R16の最新版確認を含めて更新・起動・接続を続ける。

手動取得はPrismに似た操作を目指す。サイト側の待ち時間やブラウザーの保存確認などは外部条件であり、全サイトでクリック直後の保存完了を保証するものではない。利用者へMOD検索や版の選択を任せる導線にはしない。

## 配布と公開

- **R18 取得方法**：配布専用のアカウントを設けず、共有リンクを知っている人が取得できる。Minecraftの認証は別に行う。
- **R19 配布先**：配布用サーバーを用意して運用する。将来は別のサーバー・サービスへ変更できるようにする。
- **R20 公開操作**：管理者ツールで配布内容を選択し、その内容から作った検証用インスタンスで参加確認を済ませた版だけを「公開」でアップロードする。確認結果は配布内容に紐付け、内容変更・未確認・確認失敗の状態では公開しない。

ホスティング・費用上限・具体的な接続情報は未指定。月額0円に限定する要件は採用していない。これは今すぐ契約や支払いを行う決定ではない。

## 失敗、復旧、競合

- **R21 更新失敗**：更新前にバックアップを作る。失敗時は変更前へ自動で戻し、理由を表示して起動を止める。復元後は再試行できる。
- **R22 更新取消**：成功後も直前1回分のバックアップを残し、「前回の更新を取り消す」で戻せるようにする。
- **R23 個人MODの競合**：必須MODとの競合が確認できた場合は説明する。本人が「この個人MODを一時的に無効化して続行」を選んだ場合に退避し、再確認してから起動する。退避したファイルはあとから戻せる。

同一MODの版違いの自動調整と、別MOD同士の競合への本人の選択は異なる処理である。すべての競合や起動後の不具合を事前に検出できるとは扱わない。更新取消が戻すのは参加者PCの構成であり、現在のサーバーへ参加できるかは別に確認する。

構成更新の成否と、起動へ進めるかの判定は分ける。正常に反映した後で最新版確認の通信に失敗しても、それだけで構成を自動復元しない。起動を保留して現在の構成と取消材料を保持し、再試行時に最新版を確認する。

## 実現の確認が必要な項目

以下は追加機能の要望ではなく、初期版の設計と実装で解決・検証する項目である。

1. Prismの取り込み形式、作成したインスタンスの識別、指定版の準備、外部からの起動・接続。
2. 指定パックの有効化と、Resource Pack Overrides等の既存設定との整合。
3. ファイルの取得経路と配布可否、同一MODの識別、依存関係、確認可能な競合の範囲。
4. 公開と更新の途中失敗、アプリ途中終了、復元時に後から行った個人変更の保護。
5. 「構成一致」「起動依頼」「ゲーム起動」「実際の参加」の区別と、確認できた範囲の正確な表示。

実際のMOD一覧、設定ファイル一覧、パック順は管理者が選ぶ運用データである。今回見つかった全JAR・全ZIPを配布すると決まったわけではない。
