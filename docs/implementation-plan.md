## 段階1：実現性を先に確認

小さな検証用インスタンスでPrismの取り込みから起動・接続までを確認する。既存の基準インスタンスを同期先として改変しない。

1. 初回パックを取り込み、表示名に頼らず作成先を識別できること。
2. 指定したMinecraft・NeoForge版が準備され、専用インスタンスを外部から起動できること。
3. 参加先の引数が実際に効き、表示上も起動依頼と参加成功を区別できること。
4. 対象版でパック優先順と設定変更を検証し、初回と更新後で同じ結果になること。
5. 配布用サーバーの候補で、公開前のファイルを露出せず最終参照を切り替えられること。
6. NeoForgeの版変更・途中失敗・取消で、Prismの版指定とMOD構成が一緒に戻り、個人のJava・メモリ設定が保持されること。

環境の認証や接続設定が必要な項目は、その準備段階で実施する。机上確認だけで合格にしない。

## 段階2：配布形式と管理者の公開

実際の管理者操作に沿って、基準環境選択・配布対象選択・依存と取得経路の確認・公開内容の固定・新規検証インスタンス作成・実参加と内容確認・アップロード・完成版への切替を作る。確認結果を固定した内容のハッシュへ紐付け、未確認・失敗・内容変更時には公開できない状態遷移を作る。形式と状態遷移のテストには小さな自作ファイルを使う。

検証用インスタンスの作成には参加者向けの初回作成・取得・適用処理を共用する。元インスタンスには参加に必要なファイルがあるが配布選択からは外れているケースを用意し、元環境での成功だけでは公開できないことを実サーバーで確認する。自動テストで確認記録の判定を通しても、実参加の確認済みとは報告しない。

## 段階3：参加者の同期と手動取得

専用環境の管理台帳と差分処理を作る。公式取得・自前ファイル・手動取得待ちを同じ必要ファイル一覧に集約する。個人ファイルを保持し、同一必須MODの版違いは指定へ揃える。

## 段階4：復旧と取消

失敗を意図的に起こせるテスト用Adapterを使い、保存失敗・中断・再起動からの復旧を確認する。成功後の取消と個人MODの一時退避は、進行中更新の復旧とは別の記録で扱う。

## 段階5：画面、梱包、8人規模の確認

初回案内、通常参加、必要なときだけの手動取得や競合選択、管理者公開をつなぐ。利用者へ配る形式で梱包し、開発環境のないWindows 11でも試す。最大8クライアント相当の同時取得を検証し、実ファイル量に基づく転送時間・通信量を計測する。

## 受入条件

| 分類 | 必須の確認 |
| --- | --- |
| 通常参加 | 指定版へ更新後、専用環境だけを起動して対象サーバーへ接続する |
| 同一版の再実行 | 不要な上書き・バックアップ世代の更新をしない |
| MOD更新 | 新旧どちらへの変更も指定版になり、旧版の重複JARを稼働環境へ残さない |
| 管理対象の除外 | 外された管理MOD・パックだけが稼働環境から外れ、個人追加分は残る |
| 設定 | 通常の指定ファイルは配布ハッシュと一致、指定外は保持。指定解除後もファイルが残る |
| パック設定 | 配布順・個人より高い優先度・自動有効化を満たし、無関係な設定を保つ。自動編集と丸ごと同期の重複指定を拒否し、次回の無変更確認で不要な再更新を起こさない |
| クエスト | 実サーバーの内容が参加時に届き、進捗をツールが上書きしない |
| 手動取得 | 対象版の開始用リンク、未完了ファイルの除外、誤版の拒否、全件照合後の自動再開 |
| 個人MODの競合 | 確認できた競合に限り説明し、本人の選択後に退避。復元経路を保つ |
| 更新失敗 | 取得・保存・反映・途中終了の各段階で既存状態を保つか復旧し、不完全な状態で起動しない |
| 更新取消 | 前回変更分を戻し、更新後の個人追加分を保持。無変更同期・失敗で取消材料を失わない |
| ローダー構成 | 更新・復旧・取消でPrismの版指定とMODの版を一体で扱い、必要な本体・ライブラリーの準備失敗を成功にしない |
| 配布内容の参加検証 | 固定した配布内容だけから新規環境を作り、対象サーバーへの参加と必要な機能・設定・パック・クエストを確認する。元環境の未選択ファイルで不足を補わず、参加できない構成は公開しない |
| 検証の失効 | ファイル・版・取得経路・適用方法・パック順・接続先・初回取込データの変更で再検証が必要になる。未確認、途中終了、検証後の差し替えや照合失敗では公開せず、旧公開版を維持する |
| 公開失敗 | 旧公開版が利用でき、途中ファイルが最新版として取得されない |
| 移転 | 取得URLを替えても同じpackIdの台帳・個人ファイル・専用インスタンスを維持する |
| 同時処理 | 同一インスタンスの二重更新を防ぎ、最大8人相当の取得が混在版を作らない |
| 表示 | 構成一致・起動依頼・起動確認・参加確認を誤って同一の成功表示にしない |

中核の自動テスト、Windows上のファイル・Prism連携試験、画面確認、実サーバー参加、配布物確認を分けて結果を報告する。
